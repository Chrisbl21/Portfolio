CHRIS BLANK PORTFOLIO — PART 4

DESIGN DIRECTION
A custom automotive-editorial visual system: graphite surfaces, warm off-white type, signal-orange accents, lime highlights, condensed display typography, fine technical borders, and asymmetrical layouts. The styling is intentionally more distinctive than a default student template while keeping the content readable and responsive.

FILES
- index.html: home page
- about.html: background and design approach
- projects.html: ModDrive, automotive print graphics, and digital design
- skills.html: semantic skills comparison table
- resume.html: education and experience
- media.html: video and audio examples
- case-studies.html: design process
- contact.html: accessible contact form
- css/style.css: shared responsive styling
- media/flower-captions.vtt: captions track for the video

ASSIGNMENT 4 RUBRIC CHECKLIST
- Seven internal pages with different content and page layouts
- Skills table uses semantic table markup and nth-of-type() alternating row styling
- Contact form includes a label for each control, email and telephone input types, required fields, and a submit button
- Video and audio use native controls; video includes a captions track and written description
- Content is grouped with semantic article, section, and aside elements
- Shared responsive CSS and navigation are included

BEFORE PUBLISHING
1. In contact.html, replace christopher.blank@example.com with your real preferred email address. This value is intentionally left as a placeholder because no email address was supplied.
2. The contact form uses mailto. It relies on the visitor's email application and does not store submissions on a server.
3. Video and audio samples are externally hosted, so internet access is required for playback.
4. Upload the complete folder contents to the root of your GitHub repository. Keep the css and media folders in place.
5. In GitHub, open Settings > Pages. Select Deploy from a branch, choose main and /(root), then Save.
6. After publishing, test the GitHub Pages URL, every navigation link, the contact form, and media playback.
7. Run every HTML page through the W3C validator and fix any reported errors before submitting.
